# OmniRef 数据存储说明

OmniRef 是离线、单用户应用，不包含遥测，也不会为网址卡片后台请求标题、缩略图或网页内容。

## `.omniref` 工作区

每个工作区是一个独立 SQLite 文件，扩展名为 `.omniref`。当前架构版本为 2，主要表如下：

| 表 | 内容 |
|---|---|
| `workspace_meta` | 工作区 ID、创建/修改时间、视口和缩放、架构版本 |
| `items` | 卡片通用字段、世界坐标边界、层级、样式 JSON 和版本化内容 JSON |
| `tags` | 去重后的标签 |
| `item_tags` | 卡片和标签的关系 |
| `embedded_assets` | 内嵌文件的元数据、SHA-256 和 BLOB |

保存使用串行后台队列、SQLite `DELETE` journal、`FULL` synchronous 和完整事务。交互结束会立即安排保存，普通修改使用 500ms 防抖。低于当前版本的架构不再支持打开或覆盖；比当前程序更新的架构只读打开，保存逻辑也会拒绝覆盖。

已保存工作区的页签名称始终来自 `.omniref` 文件名，文件内部不再保存独立的工作区标题。工作区打开期间，OmniRef 会持有允许 SQLite 正常读写但禁止外部删除和重命名的文件句柄。关闭页签或退出应用后，该占用会释放。

如果文件句柄被外部工具强制关闭，或者原路径下的文件被删除或替换，OmniRef 会停止该工作区的自动保存并保留内存中的修改，不会静默重建或覆盖文件。恢复原文件后可使用“重试”校验工作区 ID 并继续保存；也可使用“另存为”。原文件已丢失且工作区包含内嵌 BLOB 时，必须先恢复原文件，避免生成缺少内嵌数据的不完整工作区。

## 外部引用与内嵌副本

- 图片和普通文件默认保存绝对路径；工作区与目标之间可计算相对路径时也会同时保存相对路径。
- 打开工作区时优先解析仍然有效的绝对路径，再尝试相对路径。因此，连同相邻资料一起移动工作区时，引用通常仍可恢复。
- 文件夹始终是外部引用。
- 图片和普通文件可转为内嵌副本，单个内嵌资源上限为 512MB。
- BLOB 导入和导出使用流式 I/O，不把整个普通文件读入内存。
- 内嵌普通文件会导出到本地缓存中的只读临时副本，再交给默认程序打开。要编辑内容，应先显式导出。
- 删除卡片只修改 `.omniref` 文件，绝不会删除其引用的原文件或文件夹。
- “压缩工作区”会移除已不再被卡片引用的内嵌 BLOB，然后执行 SQLite `VACUUM`。

## 应用本地数据

默认根目录是：

```text
%LocalAppData%\OmniRef
```

其中包含：

| 路径 | 用途 |
|---|---|
| `settings.json` | 主题、语言、窗口状态、最近工作区和上次会话 |
| `Recovery\` | 尚未另存为的工作区 |
| `Cache\Thumbnails\` | 可重建的磁盘缩略图缓存，最大约 512MB |
| `Cache\Open\` | 打开内嵌普通文件时创建的只读副本 |
| `Logs\` | 本地滚动错误日志 |

缩略图和 `Cache\Open` 可以在 OmniRef 退出后安全清理。不要手工删除仍需恢复的 `Recovery` 文件。

开发、测试或便携场景可通过进程环境变量 `OMNIREF_DATA_DIR` 指定另一个数据根目录：

```powershell
$env:OMNIREF_DATA_DIR = "D:\OmniRefData"
.\OmniRef.exe
```

该设置只影响当前进程及其子进程，不会修改 Windows 注册表。
